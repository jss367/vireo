Retained generated files and grouping history

Generated-file sizes below are already included in Vireo storage above. This shared limit covers full-resolution renders, upload renders, and imported computation results. Files can regenerate from available sources; imported results may need reimporting. External editor files can contain unique edits and are preserved. Original photos, exports, recovery staging, offline copies, and editing masks are retained.

Maintenance runs hourly and after applying limits. Automatic render cleanup requires independent catalog sources to be fully readable and unchanged; offline or unverifiable sources are retained, even above the limit. Newly written files have a one-hour grace period. Age uses the latest filesystem access, write or change timestamp; 0 disables age expiry. Size 0 removes eligible generated files past the grace period; protected files remain. Grouping history retires the oldest completed snapshots first, preserving photo edits and snapshots awaiting redo. Removing snapshots makes space reusable inside the catalog; the database file may stay the same size.

      Manage Hugging Face Cache

      Vireo downloads models through the Hugging Face hub cache and then copies them into its own models folder, which is the only place the pipeline reads from. A cache entry is useful only while the model it came from is installed: it lets Repair or a re-download skip the network. Entries for models that are not installed, and files from older snapshots, are dead weight and can be removed. Installed models are removed in Settings → Models, which clears their cache entry too.
